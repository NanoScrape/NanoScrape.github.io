You want to see new second-hand listings on tutti.ch for one search, for example an IKEA shelf or a bike, without checking the site all day? Why monitor instead of searching by hand

A saved search on tutti.ch means you open the site and scroll. A scheduled run does it for you: once a day the Actor reads the newest listings for your search and returns only those posted since the last run, as a table you can filter by price and canton. Good second-hand deals, such as a used IKEA shelf or a bike below your budget, are often gone within hours, so a daily list of fresh listings beats a weekly look. This page covers the monitoring setup. For comparing prices across many listings, see the tutti.ch price comparison tutorial (German).

STEP 1

Open the Actor

  1. Open the Tutti.ch Scraper on Apify. The Actor page on NanoScrape lists every output field.
  2. Click Try for free and sign up with Google or email. Apify's free plan includes monthly platform credit, enough for a first test.
  3. You land on the Actor's Input tab. Switch to the JSON view to paste the input below.
STEP 2

Paste this input

Example: new listings for “kallax” (the IKEA shelf) across Switzerland, posted in the last 24 hours. Replace the search URL with your own.

{
  "searchUrls": [
    "https://www.tutti.ch/de/li/ganze-schweiz?q=kallax"
  ],
  "sortBy": "newest",
  "maxAgeHours": 24,
  "maxResults": 200,
  "maxResultsPerQuery": 100,
  "includeDetails": false
}
  • searchUrls: a tutti.ch search URL. For a plain keyword, use the share format https://www.tutti.ch/de/li/ganze-schweiz?q=your-keyword. For a category, region or price range, set the filters on tutti.ch, copy the URL from your browser and paste it here.
  • sortBy: newest is the default and is required for the early stop below.
  • maxAgeHours: only listings posted within the last N hours. Set it to the interval between your runs, 24 for a daily schedule. The Actor stops paging once it sees three listings in a row that are older, so it does not re-read the whole search.
  • maxResults and maxResultsPerQuery: safety caps for a single run.
  • includeDetails: leave it false for a price-and-location alert. Switch it on only if you need GPS, all photos, condition or seller fields.
URL sort wins. If your search URL already contains ?sorting=..., that value is used instead of sortBy. If you copied a URL sorted by price, the early stop does not apply, so copy it sorted by newest.
STEP 3

Run it and read the output

Click Save and Run, then open the Dataset tab. Each row is one listing. This is the sample item from the Actor's README, with the seller name left out:

{
  "id": "45678901",
  "title": "IKEA Kallax Regal weiss 4x4",
  "price": "CHF 80.–",
  "price_chf": 80,
  "currency": "CHF",
  "category": "Möbel",
  "location": "Zürich, 8005",
  "canton": "ZH",
  "postcode": "8005",
  "seller_type": "private",
  "listing_source": "tutti",
  "image_count": 4,
  "posted_at": "2026-04-18T10:00:00Z",
  "source_url": "https://www.tutti.ch/de/vi/zuerich/moebel/ikea-kallax-regal/45678901",
  "scraped_at": "2026-04-20T08:00:00Z"
}

The fields you need for an alert:

  • title, price_chf (numeric, so you can filter) and price (as shown on the ad).
  • location, canton and postcode: to keep your region.
  • seller_type: private or professional, useful if you only want private sellers.
  • posted_at and source_url: when it was posted and the link to open the ad.
  • id: the listing ID, to drop duplicates if two runs overlap.

Prices are the asking prices on the ad. A listing without a price has an empty price field.

STEP 4

Get a daily list of new listings

  1. In the Apify Console open Schedules, create a schedule that runs once a day, and attach this Actor with the input above.
  2. After a run, open the Dataset, click Export and choose CSV, or import the dataset into Google Sheets.
  3. In the sheet, filter price_chf to your budget and canton to your region, for example price_chf at most 100 and canton equal to ZH. Sort by posted_at, newest first.
  4. Open the source_url of the rows you like.

Keep the schedule interval and maxAgeHours the same. Every 6 hours with maxAgeHours 6 works the same way, only faster. If a run is skipped, listings from that gap are missed, so choose a window slightly longer than the interval and drop duplicates by id.

What it costs

Pay per result: $0.003 per listing, or $0.005 per listing with details ($5.00 per 1,000 detail listings, as shown on the Actor page). With includeDetails off, 100 listings are $0.30. Because maxAgeHours stops paging at old listings, a daily run bills only the fresh listings it returns. The current prices are on the Pricing tab of the Actor's Apify page.

Who uses a new-listings feed like this

  • Bargain hunters watch one product, such as a bike, a sofa or a camera lens, and see new asks below their limit the same day.
  • Resellers track what is newly listed in their category to source stock.
  • Shop owners keep an eye on how second-hand offers for their products appear and at what asking price.

The data is public listing data. Seller names, phone numbers or emails in a listing can be personal data, so check data-protection rules before you store or contact anyone.

Frequently asked questions

Does it return only new listings?

Yes, listings posted within the last maxAgeHours, when sortBy is newest. Run it on a schedule with the same interval to get a rolling feed of new listings.

Can I limit it to one canton or a price range?

Set the filters on tutti.ch, copy the URL from your browser and paste it into searchUrls. You can also filter price_chf and canton in the exported table.

Why do I see a few older listings?

Promoted listings can appear out of order. The Actor waits for three older listings in a row before it stops, and the maxAgeHours filter still applies to the output.

How much does it cost?

Pay per result: $0.003 per listing, $0.005 with details. 100 listings without details are $0.30. A monitoring run bills only the fresh listings it returns.

Do I need to configure a proxy?

No. The Actor reads public search pages and there is no proxy input to set.
