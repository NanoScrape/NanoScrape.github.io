How to Extract Wikipedia Data and Articles at Scale

Wikipedia holds structured knowledge on nearly every topic imaginable, and all of it is publicly accessible. The problem is that the raw MediaWiki API is fiddly to work with: pagination, language edition URLs, redirect handling, and content parsing all require custom code. The NanoScrape Wikipedia Scraper handles all of that. Give it a list of article titles, Wikipedia URLs, or a search keyword and it returns structured JSON records with the full article text, summary, sections, categories, images, Wikidata ID, and 30-day page view counts. At $0.002 per article, a thousand articles costs $2.

What you get

The NanoScrape Wikipedia Scraper connects to the official MediaWiki REST API and returns one structured JSON record per article. Each record contains:

  • Full article text as plain text and cleaned HTML, split into sections with heading levels
  • Summary and description: the one-line description and first-paragraph extract Wikipedia surfaces in search results
  • Images: thumbnail, main image, and all image URLs embedded in the article
  • Structured metadata: categories, external links, and reference citations
  • Wikidata ID: the canonical Q-ID for every article, letting you link records to the Wikidata knowledge graph
  • Geo coordinates: latitude and longitude for places, landmarks, and geographic entities
  • 30-day page views: pulled from the Wikimedia pageviews API so you can gauge article traffic
  • Disambiguation flag: identifies ambiguous pages before you ingest them

Because it uses the official MediaWiki API rather than HTML scraping, there is no bot protection to work around and no fragile CSS selectors to maintain. The same input works across all 12 supported language editions.

Use cases

  • AI and LLM training data: Wikipedia is the gold standard for encyclopedic corpora. Extract topic-specific article sets for fine-tuning or retrieval-augmented generation pipelines
  • Knowledge graphs: link entities in your database to Wikidata Q-IDs and pull in coordinates, categories, and descriptions at scale
  • Academic research: build multilingual topic corpora, track edits via last-modified timestamps, and cross-reference citations
  • Content enrichment: add encyclopedic summaries, infobox facts, or related categories to product pages, blog posts, or travel content
  • Fact-checking pipelines: verify claims against Wikipedia extracts and flag disambiguation pages automatically before downstream processing
  • Travel and geo content: extract city, landmark, and attraction data with coordinates for maps, booking sites, or itinerary builders
  • Biography datasets: scrape person articles for journalism, CRM enrichment, or historical databases and link subjects to their Wikidata records

STEP 1

Step 1: Open the actor on Apify

Go to the Wikipedia Scraper actor page on Apify. Click Try for free to open the input form. First-time Apify visitors will create a free account before landing on the input screen.

STEP 2

Step 2: Configure your query

The actor accepts three input modes. Pick the one that fits your workflow:

  • titles: an array of Wikipedia article titles (e.g., "Berlin", "Machine learning"). The scraper fetches each article directly without a search step.
  • searchQuery: a keyword string. The actor runs a Wikipedia search and returns the top maxSearchResults articles matching that query.
  • urls: an array of full Wikipedia URLs. The article title is extracted automatically from each URL.

A typical input for a research dataset looks like this:

{
  "titles": [
    "Artificial intelligence",
    "Machine learning",
    "Natural language processing",
    "Large language model"
  ],
  "language": "en",
  "includeFullContent": true,
  "includeImages": false,
  "includeReferences": false
}

To use search mode instead, swap titles for a searchQuery string and set maxSearchResults to the number of articles you want:

{
  "searchQuery": "climate change",
  "language": "en",
  "maxSearchResults": 10,
  "includeFullContent": true
}
STEP 3

Step 3: Start the run

Click Start. Because the actor calls the official MediaWiki REST API rather than rendering pages in a browser, runs are fast. A batch of 10 articles typically completes in under 10 seconds. A thousand articles finishes in a few minutes.

Wikipedia imposes no rate limits on the MediaWiki REST API for reasonable usage. The scraper runs as many parallel requests as needed and handles pagination automatically.

Input options

All input fields are optional except for at least one of titles, searchQuery, or urls.

  • titles (array of strings): Wikipedia article titles to fetch directly. Use the exact title as it appears in the Wikipedia URL, e.g., "Albert_Einstein" or "Machine learning".
  • searchQuery (string): keyword for a Wikipedia full-text search. Returns the top N matching articles.
  • urls (array of strings): full Wikipedia article URLs. The title is auto-extracted from each URL.
  • language (enum, default en): which Wikipedia language edition to query. Supported: en, de, fr, es, it, pt, nl, pl, ru, ja, zh, ar.
  • includeFullContent (boolean, default true): fetch the complete article body text and section breakdown. Set to false if you only need the summary and metadata.
  • includeImages (boolean, default true): include thumbnail, main image, and all article image URLs. Set to false to skip images and reduce payload size.
  • includeReferences (boolean, default false): include the full citation list. Useful for academic pipelines that need bibliography data.
  • maxSearchResults (integer, default 10): when using searchQuery, caps the number of articles returned.

Output field reference

  • title (string): normalized article title
  • url (string): canonical Wikipedia URL for the article
  • language (string): ISO language code of the Wikipedia edition, e.g., en
  • page_id (integer): Wikipedia's internal numeric page ID
  • revision_id (integer): revision ID of the version that was scraped, useful for reproducibility
  • extract (string): first-paragraph plain-text extract, the same content Wikipedia shows in search snippets
  • description (string): Wikidata one-line description for the article subject
  • content_full (string): full article body as plain text
  • content_html (string): cleaned HTML version of the article body
  • sections (array): per-section breakdown with title, level, and text
  • thumbnail_url (string): URL of the article thumbnail image
  • main_image_url (string): URL of the main article image
  • images (string[]): all image URLs found in the article
  • categories (string[]): Wikipedia categories the article belongs to
  • external_links (string[]): outbound links from the article
  • coordinates (object): lat and lng for geographic articles
  • wikidata_id (string): Wikidata Q-ID, e.g., Q64 for Berlin
  • last_modified (string): ISO 8601 timestamp of the last edit to the article
  • word_count (integer): number of words in the full article text
  • view_count_30d (integer): page views over the last 30 days from the Wikimedia pageviews API
  • is_disambiguation (boolean): true if the article is a disambiguation page
  • scraped_at (string): ISO 8601 timestamp when this record was produced

Automate with a schedule

To keep a dataset in sync with Wikipedia edits, schedule the actor to run daily or weekly. In the Apify console, go to Schedules, create a new schedule, and attach the Wikipedia Scraper with your saved input. The actor re-fetches each article and the last_modified field tells you which ones have changed.

For more complex pipelines, n8n can trigger a Wikipedia Scraper run, filter new or changed records, and push them to a Google Sheet, Airtable, Notion database, or vector store with no custom code.

FAQ

Do I need a Wikipedia API key?

No. The actor uses the public MediaWiki REST API, which requires no authentication and imposes no strict rate limits for reasonable usage. You only need a free Apify account to run the scraper.

How many languages does it support?

12 language editions: English, German, French, Spanish, Italian, Portuguese, Dutch, Polish, Russian, Japanese, Chinese (Simplified), and Arabic. Set the language input field to the appropriate ISO code, such as de for German or zh for Chinese.

How is this different from querying the Wikipedia API directly?

The actor handles the parts of the MediaWiki API that are annoying to work with: combining the summary, parse, and pageviews endpoints into a single call, resolving redirects, normalizing titles, handling disambiguation pages, and returning a clean unified JSON schema. You get a ready-to-use record without writing any glue code.

Can I extract data from multiple Wikipedia languages in one run?

Each run targets one language edition. To collect articles across languages, run the actor once per language with the same list of titles and then merge the results by Wikidata ID, which is consistent across all editions.

What is a Wikidata ID and why does it matter?

Every Wikipedia article is linked to a Wikidata entity identified by a Q-ID (e.g., Q64 for Berlin). The Q-ID is language-independent, so you can use it to join articles from different language editions, look up structured facts from the Wikidata knowledge graph, or link Wikipedia records to other datasets that use Wikidata as their entity layer.

Can I extract references or citations from articles?

Yes. Set includeReferences to true in the input. The actor will include the full citation list for each article. This field defaults to false because reference lists are large and most use cases do not need them.
