If Apify rotated your API token: fix n8n, Make, Zapier and API integrations

Apify reported a security incident in November 2026. If your integrations stopped authenticating, this page shows where to get your current token and how to put it back into n8n, Make, Zapier, your scripts and your webhooks.

What happened

According to Apify's status page:

  • On 9 and 10 November 2026, an unauthorized third party gained access to parts of Apify's internal systems. Apify detected the activity on 11 November, cut off access and started an investigation, which is still ongoing.
  • As a precaution, Apify revoked some OAuth connections to external integrations, including GitHub, and rotated various critical internal secrets.
  • If the investigation shows that your tokens were affected, Apify rotates them for you and notifies you. Users of integrations other than GitHub get a separate email asking them to reconnect.
Start with your inbox. If you got an email from Apify about this, follow its instructions first. The status page has the latest updates; this page only covers the practical fixes.
STEP 1

Get your current API token

  1. Open Apify Console and go to Settings → API & Integrations (console.apify.com/settings/integrations).
  2. Copy the token, or create a new one with a description, such as "n8n" or "Make". Apify's docs recommend a separate token per service, so you can rotate one without breaking the others.
  3. Don't paste tokens into chats, tickets or shared docs.

Integrations that use OAuth (Make, Zapier, n8n Cloud's OAuth2 credential) don't need the token copied. You reconnect the account instead, as shown below.

STEP 2

n8n

  • API key credential ("Apify API"): open Credentials, open your Apify API credential, paste the new token and click Save. Every workflow that uses this credential picks it up.
  • OAuth2 credential ("Apify OAuth2 API", n8n Cloud): open the credential, click Connect my account and authorize with your Apify account again.
  • Run one workflow manually to check that the Apify node authenticates.
STEP 3

Make

  • Open Connections in Make, find your Apify connection and reauthorize it (OAuth), or update the API token if the connection uses one.
  • If you prefer a clean start, open an Apify module, add a new connection (OAuth is the method Apify recommends), and select it in every scenario that used the old one.
  • Run each scenario once to confirm.
STEP 4

Zapier

  • Zapier connects to Apify through an OAuth consent screen. Reconnect your Apify connection in Zapier's app connections, or open the Apify step in a Zap, click Connect to Apify, choose your account and click Allow Access.
  • Make sure every Zap with an Apify step uses the working connection, then click Test on the trigger or action.
STEP 5

Scripts, CLI and plain API calls

Replace the old token wherever your code reads it: .env files, CI/CD secrets, server environment variables and cloud function settings. The Apify SDKs and CLI read APIFY_TOKEN.

# .env (never commit this file)
APIFY_TOKEN=your_new_token

# Apify CLI: log in again
apify login

# Plain API call: send the token in the Authorization header
curl -H "Authorization: Bearer $APIFY_TOKEN" https://api.apify.com/v2/users/me

Apify accepts the token in the Authorization header or as a token query parameter; the docs recommend the header. Search your code and saved links for token=: dataset export links and bookmarked API URLs with the old token in them stop working.

STEP 6

Apify integrations, webhooks and GitHub

  • Webhooks that Apify sends to your server keep firing. Check the receiving side: if it calls the Apify API back (for example to download a dataset), it needs the new token.
  • Integrations set up inside Apify Console (Actor or task integrations with outside services): open them and reconnect any that show an error or ask you to sign in again.
  • Actors built from private GitHub repos: the status page says to reconnect GitHub: open an Actor built from GitHub → "Change provider" → GitHub → authorize (once per account and per organization).
  • Actor or task inputs that contain a token, for example an Actor that calls another Apify account: update the token in that input.

Schedules inside Apify

Schedules and saved tasks in Apify Console run under your account. They don't use a token you handed to another tool, so a token change doesn't stop them. The exception is the last item above: if the input of a scheduled Actor or task contains a token, update that input.
