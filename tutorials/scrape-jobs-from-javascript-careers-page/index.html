How to scrape jobs from a JavaScript careers page

You open a company's careers page in the browser and see a list of jobs, but a simple scraper gets an empty page? Many careers sites are built with React, Vue or Angular and only fill in the job list after the page has loaded, or embed an applicant tracking system widget. The Website Job Extractor (Browser) renders the page like a browser, reads the open roles and returns one row per job. This tutorial shows when you need it, the input to paste and how to check the result.

When a careers page needs a browser

Some careers pages send the full job list in the page itself. Others send an almost empty page and load the jobs afterwards with JavaScript, so a tool that only downloads the HTML sees no jobs. That is the case this Actor is built for: pages built with React, Vue, Angular or similar frameworks, and pages that show a skeleton without JavaScript. It opens the page in a browser, waits for the content, and reads the job list from what is shown.

Use it as the last step, not the first, because rendering a page is slower and costs more than reading plain HTML. A sensible order:

  1. Try the plain Website Job Extractor first. It handles many careers pages without a browser. The competitor careers pages tutorial shows it step by step. It can also hand a page over to the browser Actor itself when you set enableBrowserFallback to true.
  2. If you know the page runs on a supported applicant tracking system such as Greenhouse, Lever, Workable or Personio, the Career Site Jobs Scraper reads it directly.
  3. Use the browser Actor, this tutorial, when the first one returns nothing and the page is not on a supported system. When the jobs sit in a system the Actor knows, such as Workday or Greenhouse, it reads that system's job list directly and skips the browser for that company.

STEP 2

Paste this input

Example: the engineering roles in Germany that were posted in the last 30 days on one careers search page. The address is the example from the Actor's documentation; replace it with the careers page you want.

{
  "companies": [
    {
      "company_id": "stripe",
      "company_name": "Stripe",
      "career_urls": [
        "https://stripe.com/jobs/search"
      ]
    }
  ],
  "keywords": [
    "engineer"
  ],
  "location": "Germany",
  "postedWithinDays": 30,
  "maxResultsPerCompany": 25,
  "sortBy": "newest"
}
  • companies: one item per company. company_id and company_name are labels you choose; they come back on every row so you can tell companies apart.
  • career_urls: the address of the page that lists the jobs, or of a search results page. If you already have this address, use it here. website_url is for a company homepage when you want the Actor to look for the careers page itself.
  • keywords: the job title must contain at least one of the words. location takes a city, region or country, and country names and codes both work. postedWithinDays keeps recent jobs; jobs without a posting date are kept.
  • maxResultsPerCompany: the cap per company (default 200, 0 means all). The filters run before the cap, so a cap of 25 returns the first 25 jobs that match.
  • sortBy: newest where the careers site offers a date sort; otherwise the rows arrive in the site's own order.
  • API keys: leave them empty. Without a key the Actor runs in managed mode and needs no AI account of your own.
Need the full posting text? Set includeJobDetails to true to read each job's detail page. It adds description_md and, where the posting states them, fields such as salary, workload, deadline and languages. Detail pages have their own price event, listed on the Pricing tab.
Memory: the default of 1024 MB is enough to start. If many of your pages are custom sites that need rendering, the Actor's documentation recommends 2048 MB.
STEP 3

Run it and read the output

Click Save and Run. When the run ends, open the Dataset tab. Each job is one row, marked with browser_extraction: true. This is the example row from the Actor's documentation (a placeholder company), shortened to the main fields:

{
  "company_id": "abc-123",
  "company_name": "TechCorp AG",
  "title": "Senior Frontend Developer (m/w/d)",
  "location": "Zürich",
  "employment_type": "Vollzeit",
  "department": "Engineering",
  "job_url": "https://techcorp.ch/jobs/senior-frontend-developer-zurich",
  "job_id": "senior-frontend-developer-zurich",
  "application_url": "https://techcorp.ch/jobs/apply/123",
  "confidence": 0.85,
  "browser_extraction": true,
  "extracted_at": "2026-03-09T10:00:00.000Z"
}
  • title, location, employment_type and department: the role as the page states it. Fields the page does not give stay null; the keys are always present.
  • job_url and application_url: the link to the posting and, where available, to the application. Some careers pages list jobs inline without a link of their own. Then job_url is the page address plus #job- and a title slug, and job_url_is_synthetic is true.
  • confidence: how sure the extraction is for a row that was read from a rendered page.
  • ats_system: the job system behind the page, when one was found.
STEP 4

Check the result

Besides the jobs, every company gets one summary row with _type: job_extraction_done. Open it first. It tells you how many jobs the page reported and how many were delivered, so you know the list is complete.

  • job_count and jobs_pushed: how many jobs were found and delivered for the company. jobs_total_reported_by_site is the number the site itself shows, when it shows one.
  • reason: when job_count is 0, this says why. filtered_out_by_filters means jobs were read but your keywords, location or date removed them: loosen the filters. dns_error and connection_error mean the address did not resolve or the page could not be fetched: check the URL.

When the numbers look right, add the careers page to a schedule in the Apify Console (Schedules) and run it weekly with sortBy set to newest. Use job_url to drop jobs you already have.

Frequently asked questions

Why does a normal scraper return no jobs on my careers page?

The page probably sends an empty shell and loads the job list with JavaScript afterwards. A tool that only downloads the HTML sees no jobs. The browser Actor renders the page first, so it sees what you see.

Should I always use the browser version?

No. Try the plain Website Job Extractor first, and the Career Site Jobs Scraper if you know the page runs on a supported applicant tracking system. The browser version is slower and costs more, so it is meant as the last step.

What is the difference between website_url and career_urls?

website_url is a company homepage, and the Actor looks for the careers page from there. career_urls are the addresses of the job list or a job search page, and the Actor reads them directly. If you know the address, use career_urls.

Why did a company return 0 jobs?

Open the job_extraction_done row of the company. Its reason field says why, for example that the filters removed all jobs, or that the address did not resolve.

How much does it cost?

$0.05 per company whose career site was read, plus $0.024 per job when the API key fields stay empty, as in this guide ($0.008 per job with your own AI key). Detail pages and rendered pages have their own events, listed on the Actor page.
