How to Get Only New jobs.ch Listings Every Morning

You search jobs.ch for the same role every day and want to see only what is new since yesterday. Here you set up the Jobs.ch Scraper on an Apify schedule that runs every morning, then remove the ads you have already seen by their job id in Google Sheets or n8n. What is left is a short list of new ads.

Time: 20 minutes
Difficulty: Intermediate
Cost: 20 new ads a day for a month: about $3.00
Tools: Apify Console, Google Sheets or n8n

The idea in three parts

jobs.ch can email you alerts, but an alert is a message, not data you can filter, share with a team or push into a CRM. Here you build your own alert with three parts:

  1. A saved search that returns the latest ads for your keyword and place.
  2. An Apify schedule that runs it every morning.
  3. A dedup step that compares the ads against the id values you have already seen, so only new ones land in your sheet.

The dedup step is needed because a daily search does not return only today's ads. The age filter works in whole days, and an ad stays visible for weeks. If you ran the search with no memory, you would get the same ad again every day. If you only want a one-off export of a search, the jobs.ch export tutorial is the shorter route.

STEP 1

Open the Actor

Open the Jobs.ch Scraper on Apify and click Try for free. Sign up with Google or email. Apify's free plan includes monthly platform credit. You will set up everything in the Apify Console and in Google Sheets or n8n.

STEP 2

Paste this input

Switch the input to JSON and paste the following. It is an example search for site managers (“Projektleiter Bau”) in Zürich. Replace the keyword and place with yours.

{
  "searchQueries": ["Projektleiter Bau"],
  "locations": ["Zürich"],
  "language": "de",
  "publicationDate": "3",
  "sortBy": "newest",
  "searchMode": "classic",
  "maxResultsPerQuery": 100,
  "includeJobDetails": true
}
  • publicationDate: "3" keeps ads from the last 3 days. The allowed values are 1, 3, 7 and 30. Three days instead of one is on purpose: if a run fails or you skip a day, nothing slips through, and the dedup step removes the overlap.
  • sortBy: newest puts the newest ads first, which is the setting for scheduled runs.
  • searchMode: classic matches your exact keyword. semantic (the default) also finds related terms.
  • maxResultsPerQuery: a ceiling per keyword. Set it above the number of ads you expect in three days.
  • includeJobDetails: true adds the full ad data such as posted_at and expires_at. For a plain alert you can switch it off to save cost; check the price on the actor page.

You can also add cantons, employmentType, workloadMin and companyFilter. If you already have a search set up on jobs.ch, paste its URL into startUrls instead.

Click Save & Start once to test it. Then save the input as a task (the Actor page offers “Save as a new task”) and name it, for example “jobs.ch morning check”. A schedule runs a saved task.

STEP 3

Run it, read the output and set the schedule

When the test run finishes, the Output tab shows one row per ad. This is a real item from the Actor, trimmed to the fields you need for monitoring:

{
  "id": "b122af9a-865f-410f-a553-6271e208158c",
  "title": "Wissenschaftliche/r Mitarbeiter/in öffentliche Finanzen - Städte und Gemeinden",
  "company_name": "Kantonale Verwaltung Zürich",
  "location": "Zürich",
  "canton": "ZH",
  "employment_type": "temporary",
  "workload_min": 80,
  "workload_max": 100,
  "posted_at": "2026-11-03T19:03:16Z",
  "expires_at": "2026-12-04T00:00:00Z",
  "source_url": "https://www.jobs.ch/de/stellenangebote/detail/b122af9a-865f-410f-a553-6271e208158c/",
  "source_platform": "jobs.ch",
  "scraped_at": "2026-11-12T14:15:10Z"
}
  • id: the unique ID of the ad on jobs.ch. This is the key for the dedup step. The same ID is part of the source_url.
  • title, company_name, location, canton: what you scan in the morning.
  • employment_type and workload_min / workload_max: type of contract and workload (Pensum) in percent.
  • posted_at and expires_at: when the ad went live and when it ends.
  • source_url: the link you click to read the ad.

Now schedule it. In the Apify Console open Schedules, click Create new, and set:

  • Cron expression: 0 7 * * * runs every day at 07:00.
  • Timezone: choose Europe/Zurich, so 07:00 means 07:00 in Switzerland.
  • Actions: add your saved task “jobs.ch morning check”.

Save it. From tomorrow the run starts by itself. Each run writes its own dataset, so every morning's results are kept separately.

STEP 4

Keep only the new listings (dedup by job id)

Pick one of two ways. Both rely on the same idea: keep a sheet called Seen with one id per row. An ad is new if its id is not in that sheet yet.

Option A: Google Sheets only (a minute a day)

Create a spreadsheet with three tabs: Seen, Today and New. Each morning, open the latest run in the Apify Console, export the dataset as CSV with the fields id, title, company_name, location, posted_at, source_url in that order, and import it into the Today tab (File → Import → Replace current sheet). In cell A1 of the New tab, enter:

=FILTER(Today!A2:F, COUNTIF(Seen!A:A, Today!A2:A)=0)

The result lists only the ads whose ID is not yet in Seen. Read them, then copy the rows of Today (without the header) to the bottom of Seen so tomorrow they count as known. Keep the header row in the first row of Seen and put the IDs in column A.

Option B: n8n, fully automatic

In n8n, build a workflow that runs when the Apify run finishes. In Apify, open your saved task, go to Integrations and add a webhook for the event “run succeeded” that points to an n8n Webhook node. The nodes, in order:

  1. Webhook: receives the finished run, including its defaultDatasetId.
  2. Google Sheets (get rows), renamed to Seen IDs: reads the Seen tab. Turn on Always Output Data in the node settings, so the workflow also runs while the sheet is still empty.
  3. HTTP Request: a GET to the dataset, with your Apify token as a query parameter or credential. Adjust the expression to the shape of your webhook payload:
https://api.apify.com/v2/datasets/{{ $json.body.resource.defaultDatasetId }}/items?format=json&clean=true
  1. Code (run once for all items): keeps only the ads that are not in Seen IDs:
// Input items: the dataset items from the HTTP Request node.
// "Seen IDs" is the Google Sheets node that reads the id column.
const seen = new Set($('Seen IDs').all().map(i => String(i.json.id)));
const fresh = [];
for (const item of $input.all()) {
  const id = String(item.json.id);
  if (!seen.has(id)) {
    seen.add(id); // also drops duplicates inside the same run
    fresh.push({ json: item.json });
  }
}
return fresh;
  1. Google Sheets (append rows), in a chain: first to your Jobs tab with the full rows, then to Seen with the id column. Add a Slack, Telegram or email node after the Code node if you want a morning message with the titles.
Check it once. Run the workflow twice in a row on the same dataset. The second run should add zero rows. If it adds rows, compare the id column in Seen with the dataset: they must be the same text.

What it costs

The Actor is priced at $5.00 / 1,000 job detail result. Every ad the run returns counts as a result, including the ones you already knew from the day before. Examples: 100 results ≈ $0.50. If a morning run returns 20 ads, that is 600 results a month ≈ $3.00.

Two settings keep it small. A narrow search (keyword, place, canton) returns fewer ads, and maxResultsPerQuery sets a ceiling. Using publicationDate "1" instead of "3" returns less overlap, at the price of less safety margin if a run is missed. Details are on the actor page.

Frequently asked questions

How do I get only new jobs.ch listings each day?

Run the Jobs.ch Scraper on a daily Apify schedule with publicationDate set to 3 and sortBy set to newest. Then compare the id of each ad against the ids you already stored, in Google Sheets or n8n, and keep only the ids you have not seen.

Why does the same ad show up two days in a row?

The age filter works in whole days and an ad stays online for weeks. A search for the last 3 days therefore returns ads you already saw yesterday. The dedup step by id removes them.

Which field should I use to recognise an ad?

Use id. It is unique per ad on jobs.ch and is also part of the source_url. Do not use the title, because the same employer can post the same title in several places.

What does a daily job monitor cost?

The Actor charges $5.00 / 1,000 job detail result, counted per ad the run returns. If a morning run returns 20 ads, that is 600 results a month, about $3.00.
