How to Scrape Telegram Public Channel Posts Without an API

Telegram has no public REST API for anonymous data access. To pull posts from a channel you either install the official client library (which requires a phone number and session management) or you do it the hard way. The NanoScrape Telegram Channel Scraper on Apify takes a third path: it reads the public web preview Telegram generates for every public channel at t.me/s/channelname, paginates through the full history, and returns each post as a clean JSON row. You get message text, publication date, view count, media type, and forwarded-from attribution in one dataset, with no login and no bot token required.

What you get

The NanoScrape Telegram Channel Scraper runs on Apify and reads the public web preview Telegram generates for any channel with web preview enabled. For each post in the channel history it returns a structured row with all the metadata that is visible on the public preview page. The scraper paginates automatically, so a single run can collect the full post history of a channel without any manual intervention.

  • Message text: the full post content as plain text.
  • Publication date: ISO 8601 timestamp of when the post was published.
  • View count: the number of views shown on the public channel page.
  • Media type: whether the post includes a photo, video, document, sticker, or poll.
  • Forwarded from: the original channel username when the post is a repost.
  • Message URL: direct link to the post at t.me/channel/messageId.
  • Channel URL: link to the channel's main page.
  • Scraped at: ISO 8601 UTC timestamp of when the row was collected.

One run gives you a snapshot up to a date limit you set. Remove the limit and the scraper follows pagination back through the full channel history. Schedule it to run daily and you have a continuous feed of new posts from any set of public channels.

Key input settings:

Each row in the dataset is one post. Here is what a typical row looks like as JSON:

To filter only posts from the last 7 days after downloading as JSON:

const posts = require('./dataset.json');
const cutoff = new Date(Date.now() - 7 * 86400000);

const recent = posts.filter(p => new Date(p.date) >= cutoff);

for (const p of recent) {
 console.log(`[${p.channel}] ${p.views} views - ${p.text.slice(0, 80)}`);
}
STEP 5

Schedule ongoing monitoring

A one-off run captures the current post history. To keep up with new posts, schedule the actor to run on a regular interval:

  1. In Apify Console, open the Telegram Scraper actor and click Schedules in the left sidebar.
  2. Click New schedule and give it a name such as "Daily channel monitor".
  3. Set the cron expression. For daily at 8 AM UTC: 0 8 * * *. For every 4 hours: 0 */4 * * *.
  4. In the Input field, paste your channel list as JSON (same as Step 3).
  5. Click Save. Each run creates its own dataset. Fetch the latest via the API.

To pull new posts since the last run via the Apify API:

# Fetch the most recent run's dataset
curl -s "https://api.apify.com/v2/acts/santamaria-automations~telegram-scraper/runs/last/dataset/items?token=YOUR_TOKEN&limit=200" \
 | jq '.[] | {channel, date, views, text: .text[:80]}'
For monitoring 5 channels at 100 posts per run, a daily schedule costs about $0.25 per day (one $0.15 start + $0.10 for 500 results). That runs about $7.50/month, comfortably within the Apify Starter plan.

Advanced: multi-channel monitoring and AI analysis

The actor handles two patterns that are especially useful once you move beyond a single channel.

Monitoring a topic across many channels

Telegram channels are the main distribution mechanism for many communities, including crypto projects, news outlets, and regional media. To monitor how a topic spreads across multiple channels, run the actor with a list of 10 to 20 channels and set maxResults: 200. The dataset comes back with a channel field on every row, so you can group and compare:

{
 "channels": [
 "telegram",
 "durov",
 "notcoin",
 "technews"
 ],
 "maxResults": 200
}

Tracking forwarded posts

The forwarded_from field captures the original channel when a post is a repost. This lets you identify which channels act as amplifiers for content that originated elsewhere, which is useful for influence mapping in crypto communities, media monitoring, or political research:

const posts = require('./dataset.json');
const forwarded = posts.filter(p => p.forwarded_from !== null);

const sources = {};
for (const p of forwarded) {
 sources[p.forwarded_from] = (sources[p.forwarded_from] || 0) + 1;
}

// Sort by repost count
const ranked = Object.entries(sources).sort((a, b) => b[1] - a[1]);
console.log('Top original sources:', ranked.slice(0, 10));

Key input and output fields

Input fields

  • channels (required): array of public channel usernames without the @ prefix. The channel must have Telegram web preview enabled.
  • maxResults: maximum posts to return per channel (default 100). Set to 0 for no cap (full history).
  • proxyConfiguration: proxy settings. Datacenter proxy works by default.

Output fields per row

  • id: the Telegram message ID.
  • channel: the channel username (without @).
  • message_url: direct link to the post (e.g. https://t.me/telegram/435).
  • channel_url: link to the channel page (e.g. https://t.me/telegram).
  • text: full post text as a plain string.
  • date: ISO 8601 publication timestamp including timezone offset.
  • views: number of views as an integer, from the public web preview.
  • has_media: boolean, whether the post includes any media attachment.
  • media_type: string identifying the media kind (photo, video, document, sticker, poll, or null).
  • forwarded_from: original channel username when the post is a repost, otherwise null.
  • scraped_at: ISO 8601 UTC timestamp of when this row was collected.

FAQ

Which Telegram channels can be scraped?

Only public channels with Telegram web preview enabled. A channel is eligible if you can open https://t.me/s/channelname in a browser without being asked to log in. Private channels, groups (including supergroups), and channels that have disabled web preview require an authenticated Telegram session and cannot be scraped with this actor.

How far back does the history go?

Telegram keeps full channel post history on its web preview with no documented cutoff. In practice the actor can paginate back through thousands of posts by following the cursor. Set maxResults: 0 to remove the per-channel cap and collect the complete history. Very large channels with tens of thousands of posts will take longer and cost more; test with a limit first.

Does the scraper download images or videos?

No. The actor captures metadata only: whether a post has media and what type it is (photo, video, document, sticker, poll). Actual file downloads are out of scope. If you need the media files themselves, you would need to follow the message URL and download them separately.

Can I use this for crypto community research?

Yes. Telegram is a major distribution channel for crypto projects, trading signals, and market commentary. You can scrape multiple project channels in one run, filter posts by view count to surface high-engagement content, and use the forwarded_from field to trace how content spreads between communities.

Can I run it via the API or automate with n8n?

Yes. Use the Apify REST API endpoint POST /v2/acts/santamaria-automations~telegram-scraper/runs or the JavaScript/Python SDKs to trigger runs programmatically. For n8n, use the Apify n8n node with the actor ID santamaria-automations/telegram-scraper.

How many posts per page does the scraper fetch?

Telegram's public web preview returns approximately 20 posts per page. The scraper follows the pagination cursor automatically, so you do not need to manage pagination yourself. Each page fetch is one network request; the number of requests per run is roughly (posts per channel / 20).

Does the actor handle multiple channels in one run?

Yes. Pass any number of channel usernames in the channels array. Each channel is scraped in sequence and its posts are added to the same dataset. The channel field on each row tells you which channel the post came from. Deduplication ensures the same post is never returned twice even if you re-run on an overlapping date range.
